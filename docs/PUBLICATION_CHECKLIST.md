# Public repository publication checklist

This is a local readiness checklist, not permission to publish.

- [x] Standard MIT LICENSE: Copyright (c) 2026 onchainbuilds; owner authorized original-work licensing.
- [x] Dependency notices and full pinned declaration inventory retained; dependency code, binaries, caches, keys and local operational evidence excluded except reviewed public records.
- [x] Recorded sandbox demo and deterministic fixtures labeled accurately. Historical 75-check result separated from the finalized public T4 payment and T5 rejection.
- [x] Original 9 documented as expired with non-execution corroborated; T4 settled and T5 produced ERR_RECIPIENT.
- [x] Production Rust/locks and frozen Wasm unchanged; selected recordings retain exact bytes.
- [x] Repository-relative judge instructions, license, evidence and local demo supplied.
- [ ] Owner approve the exact final manifest and omitted historical CI guide (`docs/PHASE2A_CI.md`). Apply as a normal commit preserving official history; do not push the isolated audit repository.
- [ ] Before any approved upload, verify authenticated account is onchainbuilds, repository is the intended private repository, remote state is unchanged and no unrelated content will be overwritten.
- [ ] Refresh the final staged-tree/history privacy scan immediately before approved publication. Do not upload private operational files, unresolved signed payloads or local manifests containing machine paths.
- [ ] Explicitly approve push and visibility change separately. No remote operation is authorized by this checklist.
- [ ] Review private-only manual workflow guards before any separately approved public CI change; publishing source does not require triggering CI.
- [ ] Record the two-minute demo using [the checklist](DEMO_RECORDING_CHECKLIST.md), showing the captured testnet payment and rejection, deterministic redirect fixture and recorded sandbox competition. Never imply a live LLM or live testnet payment.
- [ ] Verify current official hackathon deadline/rules, final judged commit/diff, required video and human submission fields. Public repository readiness is not completed hackathon submission.
- [ ] Obtain separate approval for the video publication, X post and application submission.

No cold dependency installation or new Linux sandbox execution is claimed in this release verification. The Windows clean-checkout judge profile uses Node built-ins and cached locked Rust dependencies. Binary/dependency redistribution would need a separate license-obligation review. No production security approval is implied.
